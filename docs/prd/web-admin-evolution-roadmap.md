# Web/Admin 演进蓝图（非微前端）

- Owner: 产品 / 前端 / 后端联合维护
- Last Updated: 2026-04-19
- Status: active
- Scope: 定义插件向 Web/Admin 演进的触发条件、阶段目标、验收门槛与回退策略

## 1. 目标与原则

### 1.1 目标

在不破坏插件主链路的前提下，把 World-Link Alpha 从“插件主形态”升级为“插件采集 + Web 主工作台 + Admin 运营后台”的三端协同形态。

### 1.2 演进原则

1. 数据和授权口径必须先统一，再扩端。
2. 插件采集链路保持可用，不进行一次性大重构。
3. Web 先做用户价值闭环，不先做后台复杂能力。
4. Admin 先做最小运营闭环，避免过早平台化。

## 3. Web 价值验证指标（G3 起）

| 指标 | 口径 | 目标值 |
| --- | --- | --- |
| 首次激活完成率 | 注册后 24 小时内完成“采集→设定→绑定作品”的用户占比 | >= 45% |
| 7 日留存 | D0 激活用户在 D7 至少有一次编辑行为 | >= 18% |
| 作品复用率 | 有 2 本以上作品并复用设定的活跃用户占比 | >= 20% |
| 错误可追踪率 | 线上错误包含可用 traceId 的比例 | >= 99% |

## 4. 阶段风险与回退

1. 风险：Web 研发挤压插件主线，导致采集体验回退。
   - 回退：冻结 Web 新需求，恢复到插件稳定性优先。
2. 风险：跨端口径分叉，导致同账号数据体验不一致。
   - 回退：以 `/v1/store` 为唯一写入入口，禁止客户端私有写路径。
3. 风险：运营后台先行过重，消耗研发资源。
   - 回退：Admin 只保留套餐与配额最小能力。
