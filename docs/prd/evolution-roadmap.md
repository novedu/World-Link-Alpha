# 产品演进路线图

- Owner: 产品 / 前端 / 后端联合维护
- Last Updated: 2026-04-27
- Status: active
- Scope: 插件向 Web/Admin 演进的触发条件、阶段目标、验收门槛与回退策略

## 1. 目标与原则

### 1.1 目标

在不破坏插件主链路的前提下，把 World-Link Alpha 从"插件主形态"升级为"插件采集 + Web 主工作台 + Admin 运营后台"的三端协同形态。

### 1.2 演进原则

1. 数据和授权口径必须先统一，再扩端。
2. 插件采集链路保持可用，不进行一次性大重构。
3. Web 先做用户价值闭环，不先做后台复杂能力。
4. Admin 先做最小运营闭环，避免过早平台化。

## 2. 目标形态

### 2.1 产品形态分工

- 插件端：网页内容采集、轻量编辑、上下文快捷操作
- 网页端：完整资产管理、批量编辑、图谱与高级分析工作台
- 云端后端：身份、存储、授权、计量、智能编排统一入口

### 2.2 架构目标

```text
Chrome Content/Sidepanel
        ↓
   background.js
        ↓
    Cloud API
        ↓
DataRepository + Entitlements + Agent Orchestrator
        ↓
   Store / Auth / Billing / Logs

Web App
  ↓ same Cloud API ↓
```

关键点：插件与网页共享同一套 API、同一套数据模型、同一套授权策略。

## 4. 分阶段路线

### Phase 0（当前阶段，插件优先）

目标：稳定插件工作流，完成云端基础能力可用。

- 保持当前消息总线：Sidepanel/Content → background
- 持续使用统一写入通道（background 网关）
- 完成云端联调与 entitlements 强校验

交付门槛：
- `/v1/store`、`/v1/auth/*`、`/v1/entitlements` 稳定
- Free/Pro 门禁误判率可控

### Phase 1（后端先行，Web 复用基础）

目标：建立"插件与网页共用"的后端能力层。

- 抽象并冻结核心 API 契约（世界/书/实体/捕获/导出/授权）
- 增加审计与计量字段（traceId、requestId、usage）
- 新增智能接口（建议）`/v1/agent/draft-entity`

交付门槛：
- 插件端不改功能即可切换到稳定 API 版本
- API 文档与消息协议文档同步更新

### Phase 2（网页 Alpha）

目标：上线网页端基础管理能力，不替代插件采集。

- 提供网页登录与会话管理
- 实现网页端世界/书/实体/捕获读写
- 导出、搜索、过滤能力与插件保持口径一致

交付门槛：
- 网页端可独立完成"管理与编辑"闭环
- 与插件对同一账号的数据保持实时一致

### Phase 3（网页主工作台）

目标：网页成为主工作界面，插件聚焦采集入口。

- 图谱、冲突检查、批量操作优先在网页落地
- 插件端保留采集与轻编辑，不承载重型视图
- 统一运营入口（订阅、配额、升级引导）

交付门槛：
- 多端一致性稳定
- 网页端承担主要活跃编辑会话

## 5. Web 价值验证指标（G3 起）

| 指标 | 口径 | 目标值 |
| --- | --- | --- |
| 首次激活完成率 | 注册后 24 小时内完成"采集→设定→绑定作品"的用户占比 | >= 45% |
| 7 日留存 | D0 激活用户在 D7 至少有一次编辑行为 | >= 18% |
| 作品复用率 | 有 2 本以上作品并复用设定的活跃用户占比 | >= 20% |
| 错误可追踪率 | 线上错误包含可用 traceId 的比例 | >= 99% |

## 6. 数据与权限一致性要求

1. 数据模型统一：`World` / `Book` / `Entity` / `CapturedItem` / `BookEntityUsage`
2. 写入规则统一：所有写入经过服务端鉴权与配额校验
3. 订阅与门禁统一：由服务端 entitlements 裁决，前端只做展示
4. 计量统一：导出、AI 调用、关键写入都要进入 usage logs

## 7. 阶段风险与回退

1. 风险：Web 研发挤压插件主线，导致采集体验回退。
   - 回退：冻结 Web 新需求，恢复到插件稳定性优先。
2. 风险：跨端口径分叉，导致同账号数据体验不一致。
   - 回退：以 `/v1/store` 为唯一写入入口，禁止客户端私有写路径。
3. 风险：运营后台先行过重，消耗研发资源。
   - 回退：Admin 只保留套餐与配额最小能力。
4. 风险：AI 能力成本失控。
   - 应对：Agent 能力统一走服务端计量与限流，不直连前端。
