## 0. 执行前扫描（强制）

每次开始执行任何事项前，必须先完成“功能完成度扫描”，再决定是否推进。

### 0.1 扫描步骤

1. 对照 `prd/TODO.md` 查目标事项当前状态（`todo/in_progress/blocked/done`）。
2. 检查该事项 DoD 是否已被证据证明达成（仪表盘、截图、日志、报告）。
3. 若事项已 `done` 且证据充分，禁止重复开发，直接推进下一事项。
4. 若事项 `partial` 或证据不足，先补证据或补缺口，不得跳过。

### 0.2 扫描记录模板

| 字段 | 说明 |
| --- | --- |
| 扫描时间 | YYYY-MM-DD HH:mm |
| 扫描事项 | SCORE-xx / TST-xx |
| 当前状态 | todo / in_progress / blocked / done |
| DoD 达成结论 | pass / partial / fail |
| 证据链接 | 仪表盘 / 报告 / 截图 |
| 决策 | 继续推进 / 先补缺口 / 跳过转下一个 |
| 扫描人 | 角色或姓名 |

## 4. 每周例会固定议程（30 分钟）

1. 指标复盘（10 分钟）：D1、D7、复用、转化、发布可用性。
2. 进度更新（10 分钟）：SCORE-01~08 状态、阻塞项、依赖项。
3. 准入评审（10 分钟）：是否允许新增需求进入本周。

## 5. 失败回退机制

1. 任一周关键目标未达成，下一周冻结新增需求，只做补短板。
2. 若连续 2 周未达成，发起“90 分冲刺复盘”，重新评估评分与路线。
3. 若 2026-05-20 未达成实绩门槛，评分自动回退并更新到总 PRD。
